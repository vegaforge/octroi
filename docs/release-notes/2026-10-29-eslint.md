# ESLint with typed rules

**Contributors.** `pnpm lint` used to print `noop`. It now runs ESLint 9 with
typescript-eslint's type-aware rules in every TypeScript package and app, with zero
warnings allowed, and CI runs it. One root `eslint.config.mjs` holds the rules; see
[ADR-2026-10-29-eslint](../adr/ADR-2026-10-29-eslint.md). `any`, `@ts-ignore`, floating
promises and async functions passed where a callback must return nothing are errors.
ESLint is not in the commit hook yet; that lands with the lefthook migration.

**Publishers** using `@octroi/proxy-middleware` with Express 4: if an `onSkip` or
`onPayment` hook throws or rejects, the error now reaches your Express error handler.
Before, it was an unhandled rejection and the request hung. `decodeReceiptHeader` now
throws on a header that is not a well-formed receipt instead of returning whatever JSON
it contained.

**Crawler operators** using `@octroi/crawler-sdk`: a paid response whose
`X-PAYMENT-RESPONSE` header cannot be decoded now rejects with
`ReceiptVerificationError`, the same as a receipt with a bad signature. Before, the SDK
reported the error to `onError` and returned the content with no receipt. `getBalance`
now throws if the USDC contract's `balance` call returns anything other than an integer,
instead of reporting a balance of 0.

**Dashboard users**: when the browser refuses a copy (for example outside HTTPS), the
copy buttons no longer raise an unhandled error, and the one-time API key panel says the
copy failed so the key can be copied by hand.

Technical shape:

- New `parseOctroiReceipt` in `@octroi/types` checks the shape of a decoded receipt;
  both receipt decoders use it. New `UpstreamErrorCode` type in the SDK for error codes
  received from a server.
- In-memory stores and trackers keep their Promise-returning signatures but are no longer
  declared `async`. `MemoryPublisherRepository.create` still rejects on duplicates.
- `apps/web-dashboard` gains a `test` script (vitest) and `next build` no longer lints.

Each behaviour change above has a test that failed before its fix. There is no manual
scenario to automate.
